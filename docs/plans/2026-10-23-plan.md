# cosmoskill — current plan

Written 2026-10-23. This file replaces `2026-10-21-plan.md`, whose steps 1
to 4 are done and whose step 5 is carried over here; that plan, the plan of
2026-10-20 and the roadmap of 2026-10-12 are kept as history. Every gate is
recorded in `docs/history/tests/gate-log.md`.

## Aim

A general observational-cosmology skill package, useful to any researcher,
with four levels (L1 `SKILL.md`, L2 `references/`, L3 `deep/` dossiers, L4
the paper) and a personal layer in which each researcher adds their own
depth. The base follows the field's own weights, not the owner's research.

Decisions that stand (owner, 2026-10-23):

- Numbers: only numbers read in a paper, each naming the paper and the place
  it was read (section, table, equation, figure, footnote or abstract). No
  number computed by an agent.
- Dossiers: no length cap; depth first, split past about 1000 lines.
- Bibliographies: no cap; `sources.tsv` lists every paper the skill cites,
  and only those.

### 2. Decide how a number that is not a paper's value passes the checker

The runs leave statements that carry a number but give no value from a
paper: generated sizes lines, notation and convention lines, table headers,
§ references, survey names (22 in the first four skills; by 2026-10-24
each finished skill leaves 1 to 21 of them, listed in its gate-log row).
The checker has no way to accept them, so the count cannot reach zero.
Choose one, then apply it to all of them:

- a marker on the statement (for example `<!-- num: not a value -->`),
  which the checker accepts and lists in a separate count; or
- new exception rules in the checker, each with a test.

One false positive is systematic: the "21" of "21 cm" (37 statements in
`cosmo-reionization-21cm` alone); an exception rule would clear it whichever
option is chosen.

A second class needs a decision of its own: **code facts** in
`cosmo-software-ecosystem` (158 statements on 2026-10-24) — versions, PyPI
release dates and code defaults whose source is a repository, an installed
package or documentation, never a paper; the same holds for facility facts
from official collaboration pages or documents (DESI, ESA, NASA, 4MOST and
SKAO pages in `cosmo-galaxy-clustering`, `cosmo-reionization-21cm` and
`cosmo-surveys-facilities`). The rule as written ("only numbers
read in a paper") would remove them all. Options: allow a named non-paper
source for code facts only (`[doc: <URL or path>, <date read>]`), or remove
them and keep the skill to what papers state.

## Rules that hold throughout

- At most two research agents at once; two Claude accounts share the
  repository: before any run, read `git log`, the `_progress.md` files and
  the end of the gate log, and take a skill only if no one holds it.
- Nothing from memory; every number read at source; a paper seen by title
  only gets no statement.
- Agents write only inside their skill; the upkeep tools run once, at the
  end of a run; the coordinator gates every run and logs it.
- The owner commits; agents do not.
