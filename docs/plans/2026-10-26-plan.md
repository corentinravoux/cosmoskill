## Steps, in order

### 1. Checker: the `[doc]` flag

- `tools/check_numbers.py` accepts a statement whose numbers are covered by
  a `[doc: …, YYYY-MM-DD]` flag: a URL, a repository path or an installed
  package with its version, then a read date. A `[doc]` without a date, or
  with a malformed one, does not pass.
- A new status `doc` is counted and listed apart (`--status doc`), sorted by
  read date, so stale facts can be found for the release-1.0 refresh. No
  staleness gate for now.
- Tests in `tests/test_numbers.py`: valid URL, valid installed package,
  missing date, bad date, `[doc]` inside a table row and in a caption.

### 2. Checker: exception rules

A rule clears one number inside a statement, never the whole statement: a
statement with another number left still fails. One rule, one test, at
least one positive and one negative case each. Candidate rules, to confirm
against the current list before writing:

- "21 cm" (and "21-cm").
- Catalogue and object prefixes: NGC, IC, UGC, PKS, 1ES, 3C, Abell, J
  coordinates, and spectral lines named by wavelength ("He I 10830",
  "Lyα 1216" only when the wavelength is part of the name).
- Instrument and field names from a fixed list: Stripe 82, LOFAR 2.0, and
  the like found in the list.
- A confidence level standing alone ("68%", "95%", "68.3%", "2σ") in a
  header, a note on intervals or a limit statement, when no other number
  follows.
- Superscripts and subscripts of notation inside a definition line
  (`η₁₀ = 10¹⁰ η`, `T₉`, `M_200c`).

A rule that would clear a real value (for example a bare percent that is a
result) is not written; those statements get a source or the marker.

### 3. Checker: the marker

- `<!-- num: not a value -->` on a statement makes it pass; it is counted
  and listed apart (`--status marked`).
- Test: a marked statement passes, an unmarked twin fails, and the marker
  on a line that holds a paper value is still listed, so the owner can
  review it.

### 4. Apply `[doc]` to code and facility facts

Two research runs at once at most, each following the brief:

1. `cosmo-software-ecosystem` (156): each version, release date and default
   re-read at its source (PyPI page, repository tag or file, installed
   package, documentation page) and flagged `[doc]`. A fact that cannot be
   confirmed today is removed, not kept.
2. `cosmo-surveys-facilities` (84), then the facility facts of the other
   skills (DESI, Gaia, ESA, NASA, Rubin, 4MOST, SKAO, WEAVE pages, among
   them in `cosmo-galaxy-clustering`, `cosmo-peculiar-velocities`,
   `cosmo-distance-ladder-h0`, `cosmo-weak-lensing`,
   `cosmo-reionization-21cm` and the hub): same treatment. Existing forms
   such as `[sec: data.desi.lbl.gov/…, read 2026-10-08]` and
   `[src: installed]` become `[doc]`.

Each run is gated (two `[doc]` statements re-read at their page) and logged.

## Decided after the plan (owner, 2026-10-26)

- `SKILL.md` has no length limit.
- A `[doc]` fact is stale two years after its read date: the checker lists
  it as `stale-doc`, which does not pass, so the tests fail until it is
  re-read (`STALE_AFTER_YEARS` in `tools/check_numbers.py`).
- A date without a day ("November 2026", "mid-2027") stays uncounted by the
  checker.
- A `[src: …]` or `[sec: …]` flag names a paper only: one that names a
  package, PyPI, GitHub, a README, documentation or a web page is listed as
  `old-src` and fails, on every statement, with or without a number. Done:
  144 old flags converted to `[doc]` after a re-read (gate log).
