# cosmoskill — release 1.0

Written 2026-10-26, on the owner's request ("Make the 1.0 release, we will
do the benchmark on another release like 1.1 or 1.2"). Base: commit
`6bf5495`. Gates are logged in `docs/history/tests/gate-log.md`.

## Owner's decisions (2026-10-26)

- A light literature refresh, not a full one: the 28 snapshots are 6 to 19
  days old.
- The coordinator commits and tags `v1.0.0` locally; the owner pushes and
  makes the GitHub release.
- The real benchmark moves to release 1.1 or 1.2.

## Steps

**R1. Light refresh** of the 28 domain skills, two runs at a time, under
`docs/agent-brief-refresh.md`: one date-sorted search per section of
`results.md` from the snapshot date to 2026-10-26; only results that change
the state of a domain; snapshots bumped. Alphabetical, with
`cosmo-tensions-anomalies` last (it synthesises the others); then the hub's
`references/field-state-2026.md` by the coordinator. Each run gated (two
statements re-read at source) and logged. Dossiers keep their own snapshot
dates.

**R2. Refresh script** `tools/refresh_status.py`: per skill, the snapshot
dates of its files and their age, the `[doc]` facts by read date and the
ones that go stale within a given horizon; `--due <days>` lists what a
refresh should cover. Tests.

**R3. Release files.** `CHANGELOG.md` (0.1 to 1.0, from the gate log and
the plans), `CONTRIBUTING.md` (the rules a contribution must pass: numbers
rule, `[doc]`, keys, sources, tests, refresh cycle), README updated, version
`1.0.0` in `.claude-plugin/plugin.json`.

**R4. Validation.** `claude plugin validate` on the repository; a
clean-account install: the marketplace added and the plugin installed in a
fresh, temporary Claude configuration directory, its skills listed, then the
directory removed. Full test suite and all checks.

**R5. Commit and tag.** One commit, tag `v1.0.0` (annotated, with the
changelog summary), not pushed.

## Later (1.1 or 1.2)

- The real benchmark: outside questions, answered blind, graded by people.
- A refresh of the dossiers under `deep/`.

## Rules that hold throughout

- At most two research agents at once; read `git log` and the `_progress.md`
  files before any run.
- Nothing from memory; every number read at source.
- Agents write only inside their skill and do not commit.
