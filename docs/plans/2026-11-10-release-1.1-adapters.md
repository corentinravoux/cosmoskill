# cosmoskill 1.1 — Optional MCP Adapters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release cosmoskill 1.1.0, in which arXiv MCP and Valency act as optional adapters that switch off silently when absent, and `cosmoskill-refine` gains an on-request extension mode that uses them to grow a layer and, through the owner's layer, the base.

**Architecture:** The adapters are used by the model through its own tools; the scripts never call them. What the model must do lives in text: a new hub reference `references/adapters.md` (loaded only for outward tasks, so day-to-day cost does not grow), one conditional step in the generated level block of every `SKILL.md`, and a new "Extension run" section in `cosmoskill-refine`. The scripts gain the state the text relies on: per-entry provenance (`via:`), a `found-via.tsv` per layer skill, a resumable `_progress.md`, layer and base sweep records (`sweeps.tsv`), `promote.py ... sweep`, and a sweep line rendered into each block by `tools/sync_blocks.py`.

**Tech Stack:** Markdown skills; Python 3 standard library only; `unittest` (`python3 -m unittest discover -s tests`); headless `claude --print` for the scenario checks.

**Spec:** `docs/specs/2026-11-10-mcp-adapters-design.md` (read it before Task 1; decisions are cited below as D1–D10).

## Global Constraints

- Repository: `~/Software/cosmoskill`, branch `main`. Owner's flow: commit straight to `main`, no feature branch, **never tag**. Push only after the owner says so (Task 11).
- Base commit: `6f2e38d` (1.0.4). Baseline: 114 tests pass.

- Every number in a skill file names its source and place, or carries `<!-- num: not a value -->`; `python3 tools/check_numbers.py --skill <skill> --list` must print nothing for every skill touched.
- Plain technical English, complete sentences (`CONTRIBUTING.md` rule 8). No emoji.
- Provenance values (`via`): exactly `valency`, `arxiv-mcp`, `web`.
- Adapter tool names are matched on the part after the server prefix: arXiv MCP `search_papers`, `read_paper`, `download_paper`, `get_paper_latex`, `get_paper_latex_section`, `search_paper_text`, `citation_graph`, `watch_topic`, `check_alerts`; Valency `semantic_search_papers`, `search_by_title`, `get_citing_papers`, `find_similar_papers`, `get_paper_by_id`, `filter_by_date_range`. A tool listed only as deferred (Claude Code: name known, schema loaded with ToolSearch) counts as present.
- Silence (D6): no answer mentions an absent adapter. Adapter state is shown only on a status request or at the start of an extension run.
- Without any adapter, behaviour is identical to 1.0.4 (no new web searches).
- Version string: `1.1.0`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A Valency identifier with a version suffix** (`2501.16852v2`) passed to `layers.py source --via valency` must be stored without the suffix in both `sources.tsv` and `found-via.tsv` → test in Task 1.
2. **A paper with no arXiv identifier, found through Valency** (`doi:10.1093/...`) must be recordable in `found-via.tsv` and accepted by `layers.py check` when it has a hand-written `doi:` row → test in Task 1.
3. **A layer `_progress.md` listing arXiv identifiers of candidates** must not make `layers.py check` demand bibliography rows for them → test in Task 2.
4. **A base with no hub** (`COSMOSKILL_BASE` pointing at the fixture base, so no `sweeps.tsv` exists) must make `layers.py sweep` fall back to the skill's snapshot date, not crash; a skill with no snapshot line reports `unknown` and exits 0 → test in Task 3.
5. **`promote.py <skill> sweep` with a layer sweep older than the base's** must refuse, exit 1 and write nothing → test in Task 4.
